# Core M6 — shared disposable transaction interface coordination proposal

Status: PROPOSED, not an approved interface or implementation. Parent V5 87f6a94918653a3417ce01205098193eb1ccb35d. Inventory M8 and Purchasing P-08 should review before adopting any extension. Core M5 remains unchanged and usable for its existing tests. Security owns actual actor/grant semantics.

## Proposed common test-only seam
- Preserve createLocalTransactionM5 and existing fixture API; add opt-in M6 exports instead of changing M4/M5 behavior. No production service imports of disposable helpers.
- Command supplies trusted server-derived scope, actor, operation effects, payload, immutable resource targets and callbacks. Include normalized resource targets (tenant, domain type, stable record ID) and operation/effect set in the canonical fingerprint alongside actor and payload. Tool label is trace context, not command identity. Scope/key remains stable across entrypoints; different actor, target or effect conflicts. Domain owners derive effects and targets, Security defines authoritative scope and identity. Reject missing/duplicate/ambiguous targets and effects, not just absent grants.
- Proposed lock target shape {type,id}; tenant identity bound to fixture instance and command scope, never a browser-supplied tenant. Domain names/IDs remain domain-owned. Shared fixture exposes lockDomain({type,id}) returning current record/revision or explicit absence, insertDomain({type,id,record}), replaceDomain({type,id,expectedRevision,record}) returning confirmed new revision. All on transaction connection. Lock all declared keys in deterministic order, including absent targets via dedicated stable lock-key table, then read current records; enforce expected revisions atomically. Domain owners specify record shape, revision policy, uniqueness (task/batch, invoice/source), and whether absence permits creation. No generic production schema.
- Proposed executor stages: validate/snapshot actor/effects/targets; authorize before claim; claim; authorize after claim; for newly claimed command acquire declared locks, reread current domain evidence, authorize after locks; execute only local effects; append immutable audit and complete minimal receipt; reauthorize immediately before transaction callback returns for COMMIT; commit; reauthorize before fresh projection. Replay never reruns effect and must authorize before disclosing results, with fresh scoped projection. Authorization receives immutable actor, operation, target set, test environment and stage, correlation; context must not substitute for authoritative scope. Literal true synthetic decision only. Missing/error/ambiguous decision denies. Real grant atomicity with database commit and delegation semantics require Security review; a precommit check is not proof of linearizable revocation.
- Proposed stored receipt is a domain-owned allowlisted minimal object (IDs, revisions, outcome identifiers only); do not store raw domain records, notes, cost or customer fields. Domain-specific receipt builder/schema should validate before completion. Projection reads current authorized view, not unrestricted receipt disclosure; separate read/field effects remain required. Projection failure after commit never implies rollback.
- Fixture outbox helper computes canonical fingerprint internally from immutable event body and event identity; same ID+same content deduplicates, changed content conflicts and rolls back. Do not trust caller-provided digest in new helper. Audit append only, denial stage metadata without payload/PII; fixture triggers do not protect against privileged database owner. Outbox intent only; no delivery.
- Adapter-classified unknown commit: inspect exact scope/key/fingerprint through a fresh connection; only matching committed receipt resolves. Absence, mismatch or inspection failure remains unknown; never reexecute automatically. Fresh grant checks before inspect/disclosure. Simulated lost acknowledgement is not actual network/restart acceptance. Explicit manual reconciliation permission remains a Security decision.
- Remote vendor effects remain outside local transaction. Catalog M8 uses existing remote mutation/idempotency/audit seam, with exact readback and no retry of ambiguous writes. No new remote writer or POST-for-read.

## Consumer coordination questions
Inventory: confirm session/task/reason typed IDs, batch uniqueness, revisions, lock ordering and minimal receipt fields; retain stock-effect separation. Purchasing: confirm invoice/source duplicate reservation keys, review revision/append-only history and minimal receipt fields; invoice approval never authorizes receiving. Both: confirm absence-lock mechanism, precommit stage and adapter method shape before implementing dependent fixtures. Catalog: confirm remote seam remains separate. Security: confirm actor namespace/delegation, resource/field/environment binding, exact effects, fresh authorization semantics and replay/reconciliation projection policy. Foundation Manager: coordinate interface acceptance and integration order; no permission aliases activated.

## Proposed targeted tests after coordination
Preserve M5 regressions; add deterministic concurrent missing/existing typed locks, stale revision/duplicate conflict, different actor/target/effect replay conflicts, cross-tool replay, post-lock denial before apply, precommit denial rolls back command/domain/audit/outbox, after-commit denial preserves effects, minimal receipt enforcement, fresh projection, computed event dedupe/conflict, matching and unresolved unknown commit inspection. Disposable local hc_test PostgreSQL only. No full combined CI rerun by Core. Dependency lockfile review separately manager-owned.

No new business permission is proposed by this internal seam. Existing exact underlying operation grants apply at every stage. Reconciliation/inspection, audit read/export, outbox dispatch and delegated execution remain separately scoped provisional capabilities in cumulative Security inventory; no actual enforcement, assignment or rename. Ordinary active employee wholesale cost visibility remains approved; modification separate. Actual legacy endpoint mapping and negative bypass tests remain gaps.
