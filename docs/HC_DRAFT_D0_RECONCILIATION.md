## Logical operations (provisional, not registry)
create, list, saveSnapshot, restore, rename, discard, draft.ack.inspect, markSubmitted, expiry/purge, audit.read independently scoped; trusted employee/tenant/environment/tool/domain/draft/schema/revision and exact fields, opaque ID, no cross-owner browse or existence leak. Create/rename bounded title; list independent metadata projection. Save whole included set current draft+edit rights, deny entire save on any unauthorized field; server admits original evidence/values, no stale denied base values or secrets. Restore after reauth current draft and read/edit intersection, withhold inaccessible identifiers/fields, fail closed if safe projection unavailable. Separate draft revision from domain revision vector. Atomic CAS, idempotency, quota, audit and durable ack, exact key fingerprint; same key same intent only current authorized original ack, no renewal; changed intent conflict. Ack inspection separate exact owner/tenant/environment/tool/domain/draft/requestKey/fingerprint metadata only, no payload, mutation or inferred success. Unknown remains unknown, no new key blind retry. Client generation and invocation guard, late ack cannot clear new edits or reveal locked workspace. Manual and periodic only current authorized session; lock/expiry hide, stop writes, clear sensitive unsaved memory on shared devices; no anonymous save/session extension/browser persistence, warn loss since last durable ack. No guarantee close save.

catalog.bulk-edit/0.1 bounded ordered records productId, nullable variantId, originalRevision, changes {field,originalValue,proposedValue}, evidence refs/completeness; no duplicate target/field. Domain server validates exact identity, revision and original values, preserve leading zeros and absent/null/empty distinction. Initial name,sku,upc,categoryId,cost,retail,msrp; supplierId/supplierSku proposal only, not mixed executable edit. Price exact decimal string+currency+master/supplier scope, PO cost excluded. Domain owns per-record changed/deleted/unavailable/revoked field conflicts, inactive and cross-row collision/unknown holds, explicit rebase/discard, no last writer wins. Safe projection independently authorized; no related-target expansion. Explicit schema migration with current authority, unknown version deny. Before submission fresh exact current record/effect/approval validation.
## Partial completion
Draft snapshot retains immutable intended item identities and per-item original revision/intent digest, no approval proof. Separate trusted outcome-recording service with current exact draft/snapshot/item/command scope, independently verify durable business outcome and original command linkage; no execution or browse. Atomic CAS append verified per-item reference (idempotent), no marking based on caller status or unknown outcome. Partial verified items remain immutable completion history, unfinished/unknown items distinct; unknown blocks automatic retry and final markSubmitted; separately authorized reconciliation only. Mark submitted only all intended outcomes verified; editing completed item requires new intent/new approval, preserve original history. No auto submission, business writes/outbox/approval via draft. Exact multi-item completion binding and revision race semantics proposed for Security/Catalog review; no new executable capability inferred.
## Lifecycle / retention
Server count/byte quota and lifecycle revision checked atomically with create/save/expiry; no auto eviction; expire at now>=deadline, no restore/save/resurrection even before purge. Authorized content save may renew idle window within original hard cap; reads, replay, ack inspection, denied saves and proposed metadata rename do not renew. Discard separately authorized; scoped standing purge only expired records under current policy, no browse, atomic with save, minimal tombstone. Encrypt transport/at rest, no raw payload/title/credentials/approval in audit; independent scoped audit read, redacted actor/operation/ref/revision/outcome/time/correlation/policy. Backup restoration cannot resurrect expired/discarded payload. Actual encryption/key/backup/legal hold/retention and ack tombstone policy require owner/Security. No live settings.
## Owner decision package (recommendations only)
- Autosave: 3s idle debounce, 30s dirty checkpoint; manual save always; bounded backoff and visible unsaved state. Catalog UX/load review.
- Retention: 14 days inactivity, 30 days hard maximum; no reads/rename/replay renewal. Decide allowed range and change ceremony, treatment of existing drafts.
- Quota: propose 20 active drafts per employee per domain and 2 MiB per snapshot, 20 MiB aggregate per employee/domain, with tenant-wide cap separately sized after load review. These are proposed limits, not approved; existing Core fingerprint 1 MiB bound does not establish draft capacity; D1 must define separate bounded serialization or lower approved cap. Reject over quota, never evict silently.
- Sharing: private employee workspace by default; no sharing/transfer in D1. Later explicit scoped read/edit/transfer with independent authority, audit and revocation.
- Backup: propose encrypted backups with 30-day maximum payload retention subject to legal/operational review, expiry/discard tombstones respected on restore, separate audit/ack retention decision; no promise immediate physical erasure. Owner chooses legal hold/recovery policy.
- Admin recovery: no admin/Owner bypass; propose separately approved strong-assurance scoped recovery, metadata first, independent reviewer for cross-owner content access, audit; no D1 cross-owner recovery until approved. Define purge service scope, discard recovery window (recommend no self-service resurrection), ack/tombstone retention at least supported retry horizon and no resurrection, audit retention and key custody.
D1 requires Manager acceptance, Security versioned draft authority, explicit owner settings and exact Catalog schema/projection; D2 initial UI separately gated. Tests: concurrent CAS/quota/expiry/purge, lost ack, partial verified completion, unknown outcome, revoked field, no existence leak, stale schema/revision, lock/reauth, no business side effects, redacted audit/backup recovery, keyboard/mobile and dirty status. No persistence or CI for docs alone.
