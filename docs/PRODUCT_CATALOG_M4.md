# Product Catalog M4 — asset evidence (internal draft)
Read-only normalized single-tenant fixture metadata. Product/variant targets remain separate; no automatic parent fallback. IMAGE roles PRIMARY/GALLERY use explicit integer slots, MANUAL/DOCUMENT use SUPPORTING with null slot. Availability is observed AVAILABLE/MISSING/UNKNOWN, never inferred from reference presence. Duplicate asset IDs retain observations; conflicting metadata, duplicate image slots/references or multiple primaries invalidate completeness. An available explicit primary is returned only with trusted complete coverage. No inferred primary. Opaque DRIVE_FILE/STORAGE_ID values are restricted identifiers, not paths or permissions. HTTPS metadata requires canonical URL on a trusted exact host allowlist, no credentials, query, fragment or non-default port. This is NOT an SSRF defense, download permission, or browser rendering authorization; no network access occurs. Future retrieval requires separate authorized resolver, DNS/redirect/content validation and source access checks. Signed URLs are deliberately not represented. No upload/write proposal executor. M5 requires manager review of DTO/coverage, Core/Security approval and representative test-tenant read authorization; until then only offline consumer parity preparation is allowed. Existing consumers and writers untouched.
