# HC-DRAFT/0.1 — D0 candidate, not approved API
Contract only; no storage, routes, registry activation or policy settings. Core owns lifecycle, persistence mechanics, revision, ack and recovery orchestration; Catalog owns bulk-edit schema, revisions, conflict UI and submission; Security owns actor/session/field admission, retention/data protection policy; Manager reconciles before D1.
## Logical operations
create(domain,schemaVersion,title,requestKey), list(domain,cursor), saveSnapshot(draftId,expectedDraftRevision,requestKey,payload,baseRevisions), restore(draftId), rename(draftId,expectedDraftRevision,requestKey,title), discard(draftId,expectedDraftRevision,requestKey), expire/purge(policyRevision), markSubmitted(draftId,expectedDraftRevision,verifiedCommandReference). All logical names provisional; every operation independently authorized by current Security. Server-derived exact owner employee, tenant, environment, domain namespace; opaque ID, no cross-employee sharing or existence leak. Titles/list metadata independently projected; no caller-supplied ownership. Separate privileged maintenance authorization, no implicit admin bypass.
## Snapshot
Versioned envelope draftId, owner scope, domain/schemaVersion, bounded title, snapshotRevision, domain payload, base record IDs and revisions, createdAt,lastAcknowledgedAt,expiresAt,retentionPolicyRevision,status; server controls identity/time/revision. Validate schema and field admission before save, no reusable credentials, tokens, approval proof, executable jobs or raw payment secrets. Atomic snapshot + idempotency record + redacted audit; same key/same exact input yields original acknowledged revision subject to current access, different input conflict, no last-writer-wins. Expected revision compare-and-swap, quota/expiry serialized with save. Ack only after durable commit/readback: draftId, revision, acknowledgedAt, expiry, requestKey; unknown ack means inspect current authorized snapshot/idempotency evidence, never assume save or overwrite. Out-of-order responses cannot clear dirty newer edits.
## Recovery
Manual save and periodic checkpoints while authenticated; stop writes and hide sensitive fields on lock/expiry; no anonymous rescue or session extension. No unprotected browser persistence. UI dirty/saving/saved/unsaved/conflict/locked/expired, last acknowledged time, warning that edits since ack may be lost. Browser close best effort only. Reauthenticate then independently authorize list/restore and current field projection; revoked fields not disclosed, fail closed when safe projection unavailable. Domain compares current authorized record revisions, reports changed/deleted/unavailable without unauthorized existence leak; explicit review/rebase or discard, no automatic overwrite. Snapshot revision distinct from business record revisions. Schema migration explicit validated/versioned, unknown version denied, no silent loss.
## Retention
Server-owned bounded count/size quota, inactivity expiry and hard lifetime, policy revision, atomic expiry/save race; reads never extend expiry. Expired inaccessible before purge, no resurrection; purge payload with audited minimal metadata and reviewed backup retention. Explicit save may extend within cap. 3s debounce/30s checkpoints, 14-day idle/30-day maximum are proposals only; exact limits, purge/recovery, at-rest protection and audit retention require Security/owner agreement. Fail closed on unavailable policy.
## Business separation
No draft action performs business write, payment, stock change, remote call, approval or outbox. Final submit separately rederives exact current intent/effects/revisions, fresh authorization and approval; changed intent new approval. No automatic submit. Mark submitted only on verified business outcome, store non-secret command linkage; unknown outcome blocks automatic resubmission pending authorized reconciliation.
## D1/D2 acceptance gates
Atomic ack/replay, concurrency, quota and expiry, wrong owner/tenant/domain, revoked field, lock/expiry, restore reauth, stale/unknown policy, schema mismatch, changed/deleted records, lost ack, interrupted save, audit redaction and zero business side effects; Catalog UI keyboard/mobile and explicit conflict choice. Security must specify versioned draft access/projection and retention policy; #121 execution contract not extended implicitly. Catalog must specify exact variant/field schema and base revision evidence. No storage until Manager accepts D0.
