# Product Manager January fixture — owner test

**Offline only.** No actual login, production navigation, network requests, vendor changes, PDF rendering or printing. All eight records, roles and provider evidence are fictional; browser refresh resets this workspace. The latest Owner's HTML, JS and CSS form the UI reference. This fixture is intentionally a separate current candidate; the older recovered PR #28 root UI and tests are retained, unmounted, for regression/reference.

## Run without installing anything
Open `Product_Manager_January_Fixture.html` in a regular local Chrome or Edge tab (double-click after downloading). This single file contains CSS, scripts and the pinned Catalog and Avery modules. Do not enter real data or PINs. If your browser policy prevents local HTML scripts, report it; do not disable security settings.

Source build (Node 22, no npm installs): from `product-manager/fixture/` run `node build-standalone.mjs Product_Manager_January_Fixture.html`. Test: `node --test fixture-runtime.test.mjs fixture-ui.test.mjs`. The modular `index.html` is intended for a loopback static server serving only this folder; the bundled file is preferred for owner use.

## Owner acceptance checklist
1. Search `Fixture Airliner` to see one product. Enter `00000123` and click Exact lookup (or Enter) for the leading-zero store tag; exact selection is SKU `000001`. `SHARED-DEMO` shows two candidates and clears any previous exact selection. `0000000000041` (EAN), `0000000000052` (ISBN), `00000000000063` (GTIN), and `FIXTURE-ALIAS-007` (alias) are additional fictional lookups. A nonexistent identifier must show no exact match.
2. Sort by retail or cost; try Columns, resize/reorder headers, filters with AND/OR, and hide inactive/selected-only. Select a row and change its details view. Profile layout and filter changes are intentionally in-memory.
3. Choose Morgan (individual editor). Edit cost and retail in the grid, then click Review Changes; confirm the before and after values and Apply to fixture only. Check results, and verify bulk is disabled. Try invalid currency (negative or more than two decimals), then undo one field and discard drafts. Taylor is read-only. Roles are not employee login or security proof; resolve drafts before switching role.
4. Choose Alex (bulk editor). Select two rows, Bulk Edit Selected, choose Description, Supplier, Category, Cost or Retail, and stage a value. Review each target. Choose a product under Simulate one failed product, then apply. Confirm one successful result and one remaining draft. Close results, review the remaining draft and explicitly apply it with no simulated failure. No automatic retries. UPC and supplier item code bulk edits are intentionally disabled pending actual field capabilities.
5. Select one or more rows with no pending drafts, click Prepare Labels, choose quantities and start row/column. Verify `poId: SELECTED_PRODUCTS`, `templateId: Avery_5960`, leading-zero SKU, current price, and quantities in the prepared JSON. It is a request preview only; no PDF or printer is invoked. The fixture blocks label preparation while any drafts remain, so uncommitted prices cannot be mistaken for current prices.
6. Try the sidebar and field guide, smaller window, keyboard controls, 100/125/200% native browser zoom. Check actual rendered layout, focus, editing, column drag/resize, categories, multiline description, filter selection, role transitions, results and refresh reset. Report issues; current automated UI tests use simulated DOM, not browser rendering.
